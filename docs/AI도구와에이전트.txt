AI 도구를 어떻게 활용했고 어떤 에이전트를 만들었나

[사용한 AI 도구와 활용 방식]

- Claude Code (Anthropic의 명령줄 도구)를 실행 기반으로 썼다
  플러그인은 Claude Code의 확장 구조 세 가지로 이루어진다. 스킬(SKILL.md 절차서, 17개), 에이전트(agents/*.md, 3개), 자동 실행(hooks.json, 2개). 사용자는 자기 프로젝트에서 Claude Code를 열고 /ai-dev-assistant:onboard 처럼 스킬 이름을 부른다. 모델은 사용자의 Claude Code 설정을 따른다.

- 역할을 "메인 세션"과 "읽기 전용 작업자"로 나눴다
  메인 세션(사용자와 대화하는 Claude)만 파일을 쓰고 사용자에게 묻는다. 작업자 에이전트는 읽기 도구(Read, Grep, Glob, 일부 git 명령)만 허용해 코드를 읽고 근거를 붙여 보고만 한다. 읽을 것이 많은 단계는 작업자 여럿에게 관점을 나눠 주고 동시에 돌린 뒤 메인이 취합한다. 실수가 나도 파일을 건드리는 주체가 하나라 되돌리기 쉽다.

- 판단은 LLM이, 결정적 처리는 Python 스크립트가 맡는다
  논문 수집, 데이터베이스 기록, 대시보드 html 생성, 문서 규칙 검사처럼 매번 같은 답이 나와야 하는 일은 표준 라이브러리만 쓰는 스크립트(plugin/scripts/, 16개)가 한다. LLM은 판정(선별 in/out), 요약, 분류, 문서 작성처럼 판단이 필요한 곳에만 쓴다. 비용이 줄고 결과가 재현된다.

- 교차 검증을 절차에 넣었다
  탐색(explore), 계획(plan), 리뷰(review), 디버그(debug), 테스트 설계(test-design)는 관점별 작업자가 낸 결과를 다른 작업자가 반대 관점으로 검증하는 라운드를 둔다. 리뷰는 관점 도출, 분석, 검증의 세 라운드로 거짓 양성을 거른 뒤 한 번만 보고한다.

- 외부 자료는 공개 API와 브라우저 내보내기로 받는다
  arXiv는 공개 API로 직접 수집한다. IEEE Xplore와 Google Patents는 검색 결과를 CSV로 내보내 반입한다. Claude Code에 브라우저 조종 도구(Claude in Chrome)가 있으면 스킬이 검색과 내보내기까지 직접 하고, 없으면 사용자에게 절차를 안내하고 파일을 받는다. 논문 전문(PDF)은 저장소에 두지 않는다.

- 사용자만 정할 수 있는 것은 "판정요청" 문서로 모아 한 번에 묻는다
  되돌리기 쉬운 것은 권고대로 진행하고, 저장소를 어디에 올릴지나 코드 수정 여부처럼 사용자 몫인 결정만 예시, 선택지, 권고를 붙인 문서로 묻는다. 답은 문서의 % 줄에 번호로 적는다. 대화가 길어져도 결정 이력이 파일로 남는다.

- 플러그인 자체도 같은 방식으로 Claude Code로 만들었다
  설계 문서와 판정요청으로 방향을 정하고, 실행 계획을 8단계로 나눠 구현했다. 스크립트는 테스트를 먼저 쓰고 실패를 확인한 뒤 구현하는 순서(테스트 주도 개발)로 112건의 테스트를 두었다. 단계마다 별도 모델(Claude Opus) 작업자가 변경분을 검토하는 라이트 리뷰를 돌려 지적을 반영했다. 실제 코드 사본(시험장)에서 스킬을 비대화 실행(claude -p)으로 돌려 절차서를 고쳤고, 화면은 헤드리스 Chrome 스크린샷으로 확인했다.

[만든 에이전트 (agents/)]

- explorer: 코드 탐색 작업자
  한 관점(구조, 데이터 흐름, 인터페이스, 제약 등)을 맡아 코드를 읽고 파일:줄 근거를 붙여 보고한다. 도구는 Read, Grep, Glob과 git log, show, diff. 파일을 쓰지 않는다.
  쓰는 스킬: onboard(관점 4개 병렬), explore(탐색 4명과 교차 검증 4명), wiki(출처별 수집 작업자 N명).

- paper-reader: 논문 읽기 작업자
  논문 한 편과 프로젝트 프로파일만 읽고 선별 판정(in, out과 이유) 또는 전문 분석(고정 선택지 분류표, 10줄 요약, 모듈 대응, JSON)을 쓴다. 도구는 Read, Grep, Glob.
  쓰는 스킬: paper-screen(배치를 나눠 병렬 판정, 메인이 무결성 검증 뒤 기록), paper-analyze.

- reviewer: 변경 검토 작업자
  변경 범위를 한 관점에서 읽고 파일:줄과 심각도(높음, 중간, 낮음)로 보고한다. 도구는 Read, Grep, Glob과 git diff, log, show.
  쓰는 스킬: review(세 라운드), speed-opt와 robustness-check의 결과 검증.

- 메인 세션의 역할
  작업자 결과의 취합과 교차 검증, 파일 쓰기, 프로파일 갱신, 판정요청 작성. 에이전트가 아니라 사용자와 대화하는 Claude 자신이다.

[자동 실행 (hooks.json)]

- 세션 시작: _pm/TODO.md 에 확인 시각을 적고 미완 작업 요약을 대화 문맥에 넣는다 (pm_stamp.py)
- md 파일 수정 뒤: 줄표와 가운뎃점 같은 문서 규칙 위반을 찾아 경고만 낸다, 막지 않는다 (doc_check_hook.py)

[스킬과 작업자의 대응]

- 관리: pm, doc-check, dashboard (작업자 없음, 스크립트 중심)
- 문서화: onboard(explorer 4), explore(explorer 8), wiki(explorer N과 작성 작업자 N)
- 조사: paper-search(스크립트), paper-screen(paper-reader N), paper-analyze(paper-reader N)
- 실험과 최적화: idea-apply, speed-opt, robustness-check(reviewer), param-opt(스크립트 최적화기)
- 절차: plan(작업자 4), review(reviewer, 세 라운드), debug(가설별 작업자 4), test-design(관점별 작업자)
