original decoder와 .py decoder의 로직 차이

작성: 2026-08-06 22:45:17 비교 대상 .py: 이 폴더의 src/decoder.py decoder_main() (syndrome-aided, 본체 커밋 72b825a에서 파생하여 2026-08-06 개정, 2SD/3SD는 2026-08-09 구현) (DAO 연동 빌드인 __AUTO_LLR_OPT__ 경로 기준) 비교 제외 (사용자 지정): dual update, pipeline(2~3 column store 지연), CRC, HCU, puncturing, shortening

1. 차이가 있는 항목

#항목original현재 .py비고
1지원 디코딩 모드HD, 2SD, 3SD, 1.5SDHD, 2SD, 3SD (SD의 Pre 단계와 restart 규칙 포함, 2절 10번)1.5SD는 계획 없음. SD의 Jump_Iter(전력 절감 연동 iteration 점프)는 전력 기능이라 미구현 (#5와 같은 사유)
2BF (hard bit flipping) 구간비 AUTO 빌드: syn_weight < syn_th_BF0이면 BF 진입, iteration 1~4에서 dv>5 컬럼은 1-bit precision (V2C, C2V magnitude 최대 고정), iteration 5(ITER_MAX_HBF+1)에서 추가 edge clear.
AUTO(DAO) 빌드: ITER_MAX_HBF=0, flag_BF_on 상시 LOW로 비활성		미구현py는 AUTO 빌드와 동일 동작이므로 DAO 연동 기준으로는 차이 없음
3error floor 감지 상태머신Adjust_HD_Floor_Type(): CSW가 임계값 이하로 연속 유지되면 state_hd_error_floor_set 전환, 비 AUTO 빌드에서 테이블 세트 전환에 사용 (__HD_FLOOR_SET__)미구현AUTO 빌드의 그룹 선택(iteration/CSW)에는 영향 없음, corner 추적용 부수 기능만 남음
4테이블 세트 전환 방식비 AUTO 빌드: iteration 1~4, 5~8 하드코딩 그룹과 FLAG_HD_*_SET 플래그 전환.
AUTO 빌드: LLR matrix 파일의 iteration/CSW 그룹 (Get_Cur_LLR_Idx_FILE)		AUTO 경로만 구현 (LLR matrix 파일 기반)DAO 운용 기준으로는 동일
5power stoppingstopping_criteria = CYCLE 모드에서 일정 지연(POWER_STOPPING_DELAY) 후 채널 LLR을 CH_LLR_MAX로 교체하는 전력 절감 로직미구현 (항상 테이블 ch 값 사용, stopping_criteria = ITER 상당)FER 실험 목적에는 영향 없는 전력 시뮬 기능
6iteration 0 (신드롬 계산)메시지 전달로 계산: VN_Cal_Pre가 read bit 부호를 실은 ±EDGE_MAG_3을 보내 check_sum에 누적한 뒤 syndrome 레지스터로 복사**H·r 직접 계산**으로 대체 (등가)결과 동일, 구현 방식만 다름. iteration 번호는 py가 1부터 시작 (original의 iter 1에 대응)
6bHD의 iteration 1 edge clearHD는 iteration 1에서도 CN 상태를 클리어 (Ref-C와 RTL의 iteration 0 저장 차이를 없애는 보정, decoder.cpp:6570 주석)하지 않음 (전 모드 restart만 클리어)사용자 결정 (2026-08-09). py는 iteration 1의 CN 상태가 초기값 그대로라 클리어 유무가 산술 결과를 바꾸지 않음 (HD 회귀로 산출물 동일 확인)
7성공 판정과 종료Ref-C는 CRC 검출로 종료 (CRC 자체는 비교 제외 대상)genie: 매 iteration 결정을 정답(all-zero)과 비교, 일치하면 그 프레임 성공 확정 후 배치에서 제외genie는 CRC 조기종료의 이상화 대응 (미스검출 없음). 사용자 결정 (2026-07-30, README 확정 결정 기록)
8dv 미매칭 처리Get_VNU_LLR_SET_FILE: column degree가 dv_from/dv_to 어느 구간에도 없으면 조용히 첫 구간(col_idx 0) 사용에러 발생사용자 결정 (2026-08-06): 조용한 대체는 실수 유발이라 재현하지 않음
9LLR 정밀도 빌드3-bit(EDGE 4레벨, th 3개)와 __4_BIT_LLR__(EDGE 8레벨, th 7개) 두 빌드사람이 만든 파일은 3-bit 전용 (EDGE {7,5,3,1}, th 3개 아니면 에러). 균일 생성물(파일명 uniform)은 n-bit 레벨 지원사용자 확정 (2026-08-06): LLR은 3-bit만 사용, 4-bit 확장 계획 없음

2. 등가로 확인된 항목 (차이 없음)

#항목동작 (양쪽 동일)
1메시지 도메인syndrome-aided flip 도메인: 모든 메시지가 초기 read bit(r) 기준 상대값, r 고정
2VN 판정sum_t = ch(항상 +) + Σ C2V, sum_t <= 0이면 bit 반전 (동점 반전 포함, VN_Cal_HD 원문. 2SD/3SD는 비트별 region이 ch 열을 선택할 뿐 판정식 동일: VN_Cal_SD)
3C2V signsynd ⊕ check_sum ⊕ edge_sgn. edge clear iteration에서는 edge_sgn 미포함 (클리어로 0)
4edge clear (restart)restart iteration에서 min1/min2=최대 레벨(RESET=edge_mag 최댓값, 3-bit에서 V_VERY_STRONG=EDGE 7), min1_pos, check_sum, edge sign 클리어, syndrome은 유지 (SD 원본은 syndrome을 지운 뒤 Pre 단계가 같은 값 H·r을 재계산하므로 관측 등가). HD의 iteration 1 클리어는 1절 6b 참조
5restart row (HD)-1 값 그대로 산술 사용: ch=-1(채널 기여 거의 0), th=-1(전 메시지 최대 레벨), 순수 syndrome bit-flip iteration
6CNU 갱신column 진행 중 즉시 remove-old, insert-new. min1 교체 시 min2=RESET(기존 min1을 min2로 내리지 않는 HW 특성), <= 비교 (CNU_Remove_Old_Sgn, CNU_Update_New_Mag 원문)
7VNU 양자화`\sum_t − VNU_in\`를 th 목록과 캐스케이드 비교해 edge_mag 레벨로 양자화 (3-bit에서 >= th1 → 7, >= th2 → 5, >= th3 → 3, 그 외 → 1). 값이 0이면 sign은 VNU_in에서
8CSWΣ(check_sum ⊕ synd) (Compute_CSW 대응), iteration 1 진입 시 prev_CSW = \synd\
9테이블 row 선택iteration으로 그룹 선택 후, ITER 타입은 iteration 구간, CSW 타입은 아래 row부터 prev_CSW <= 임계값 첫 매칭 (Get_Cur_LLR_Idx_FILE 원문)
10SD Pre 단계 (iteration 0과 SD restart)VNU 출력의 부호는 read bit, 크기는 region 채널 magnitude (3-bit 기준 2SD [5,1], 3SD [7,5,3,1] 고정 상수, 파일에서 읽지 않음)를 min1/min2에 심고 check_sum과 edge sign은 0으로 남김. SD restart는 그 iteration의 row 값(ch, th)을 쓰지 않고 판정을 read bit로 되돌리며 종료 시 CSW=\syndrome\(VN_Cal_Pre, V2C_Store, Is_Iter_Type_Init 원문)
10max_iterLLR matrix 파일의 마지막 iter_end가 결정
11수치 표현original은 V 코드 {3,2,1,0}로 저장 후 C2V에서 EDGE {7,5,3,1} 변환, py는 EDGE 값 직접 저장 (단조 일대일 대응이라 등가)
12min1_pos 초기값original은 Get_Default_Min_Pos, py는 -1. 클리어 직후 min1=min2=RESET이라 어느 쪽을 읽어도 결과 동일
13genie 성공 프레임 마스킹py 전용 속도 최적화 (성공 프레임을 배치에서 제외), 결과 불변
