B. 알고리즘 요약

  1. 대상: (3,6)-regular QC-LDPC(N=1296, z=54) 및 WiMAX rate-1/2 irregular QC-LDPC(N=2304, z=96), AWGN, 20 iter, q=4bit 메시지.
  2. 문제: LDPC HW서 메모리·인터커넥트가 면적/지연/전력을 지배 - 메시지 저장 정밀도를 낮춰 비용·throughput을 개선하고 싶다.
  3. 핵심기법: NS-FAID - CN 갱신은 MS와 동일하되, VN 갱신 출력에 비전사(nonsurjective) framing function F: M→M을 적용해 이미지 집합을 좁혀 메시지를 w = log2(W)+1 bit로 저장.
  4. 핵심 정의: F는 홀함수·비감소(Prop.1) LUT [|F(0)|,F(1),...,F(Q)]로 완전결정, weight W < Q+1이면 비전사. OMS/POMS 등 기존 기법이 F의 특수해로 통합됨.
  5. 확장: 기존 정의를 F(0)=±λ까지 허용해 2bit 같은 극저비트서 성능 대폭 개선 - w=2 best F=[±1,1,1,1,1,6,6,6].
  6. irregular 확장: VN degree별 다른 F_dv 사용, 이미지 포함관계 제약(Im(F_dv)⊆Im(F_max))으로 CN 메시지도 w_max bit로 저장 - layered에 적합.
  7. 최적화: DE로 framing function F와 채널 gain factor μ를 공동 최적화, η-threshold(BER=1e-6) 기준 방대한 후보(irregular 7M+)를 pruning 탐색.
  8. HW: layered QC-LDPC 두 아키텍처(pipelined / full-layer), MS의 SAT 블록을 FRA(framing)로 교체 + DE-FRA(deframing) 추가, compressed CN 저장(min1/min2/sign/idx) 지원.
  9. 결과: 65nm ASIC 합성서 (3,6) NS-FAID-3는 MS 대비 BER +0.19dB에 TAR 18.88~31.61%↑, NS-FAID-2는 -0.21dB에 TAR 34.37~58.75%↑. β-memory·CNU 면적 대폭 감소. WiMAX NS-FAID-332는 NTAR 45.86 Gb/s/mm2/iter.
  10. 한계: q=4bit MS 기준 결과이며 절대 throughput(Gbps) 본문 수치 없음, framing/deframing 추가블록이 이득 일부 상쇄, 부호마다 DE 재최적화 필요.

framing function F(저정밀 메시지 저장)decoder.cpp VN_Cal_HD() 등, decoder.h Get_VNU_*VN 출력 재양자화 지점에 F/deframe 삽입 - min-sum 루프 그대로 두고 이식 가능(난이도 낮음)
Min-Sum CN 갱신(min1/min2/sign)decoder.cpp CNU_Update_New_Mag(), C2V_Cal_New_Sgn()우리 min-sum과 동일 - NS-FAID는 CN 연산 미변경, 저장정밀도만 축소
이터레이션 루프 / layered 스케줄decoder.cpp LDPC_Decoder()우리도 dual-update(parity 교대) layered - compressed CN 저장 구조 정합
DE로 F·gain μ 공동최적화 → iteration별 LLR 테이블ecc_data.h PARAM_LLR, decoder.cpp Get_VNU_Table_Idx()우리 적응형 LLR 테이블과 개념 겹침 - framing LUT를 테이블화해 통합 가능
gain factor 양자화 map ϕchannel.cpp Set_LLR_Th(), Set_R_Offset()채널 LLR 양자화 지점 - 저비트 저장 시 재조정 필요
부호구조 로드(QC base matrix)ecc_top.cpp Load_PCM()부호는 그대로, 디코더 저장정밀도만 변경

적용 가치: 중간 - framing function은 min-sum 루프를 유지한 채 VN 출력 재양자화만 추가하는 저난이도 이식이고 메모리/CN면적 절감이 Prime ECC의 실병목(메모리·라우팅)과 직결되나, q=4bit MS 기준이라 우리 hard/2SD/3SD 저비트 LLR·고rate 부호에서 DE 재최적화가 필요하다.
