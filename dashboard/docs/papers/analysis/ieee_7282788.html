B. 알고리즘 요약

  1. LDPC 코드의 인코딩(precoding+encoding)은 parity check matrix H를 systematic form H_sys=(H_P H_I)로 변환 후 H_P p = -H_I m을 푸는 문제.
  2. 기존 RU(Richardson-Urbanke) 알고리즘은 approximate triangular matrix(ATM)로 변환해 순차적으로 O(N+δ²)에 인코딩하지만 병렬화가 안 됨.
  3. 제안 기법은 H를 K-way singly-bordered(SB) block-diagonal 형태 H_KSBBD로 변환(row/column permutation)해 K개의 독립적 소규모 선형방정식으로 분해.
  4. 변환은 H의 Tanner graph를 row net model 하이퍼그래프로 표현하고, PaToH로 K-way 하이퍼그래프 파티셔닝(balanced, cutsize 최소화)을 풀어 얻음.
  5. 대각 블록 A_i 각각에 RU 알고리즘을 재적용(ATM(A_i)→(A_i^ATM,P_i,Q_i,Φ_i^{-1}))해 parity part H_P, information part H_I 구성.
  6. M_{K+1}=0인 경우(테두리 블록 소멸) 각 서브블록의 p_i가 완전히 독립적으로 풀려 K-프로세서 완전병렬 인코딩 가능; M_{K+1}>0이면 먼저 p_{K+1}을 구한 뒤 나머지를 병렬로 풂.
  7. 복잡도는 곱셈수 μ_i, 덧셈수 α_i로 정의(wt(·)=비영원소 수, S(·)=비영행 수 기반).
  8. 별도 학습/최적화 절차 없음 (PaToH는 기존 휴리스틱 파티셔너 사용).
  9. 결과: PEG 기반 코드 등 11개 예제에서 2-way 분할 시 δ(gap)는 RU 단일처리와 유사하거나 소폭 증가, 프로세서당 연산량은 RU 전체의 약 절반씩으로 균등 분배됨(예: PEGReg504x1008에서 RU 4599/3542 vs 두 프로세서 각 2369/1802, 2384/1819).
  10. 한계: 실제 wall-clock speedup·HW 구현 없이 연산 카운트 비교뿐이며, SC-LDPC로의 확장은 future work로 남김.
