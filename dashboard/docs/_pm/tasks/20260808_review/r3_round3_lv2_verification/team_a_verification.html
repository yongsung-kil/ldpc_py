Round 3 검증 · 팀 a (numeric) — 수치 발견과 처방의 독립 재확인

작성: 2026-08-08 16:46:31 대상: A-1, A-2, A-3, A-4, A-5, A-11, A-6 처방 (Round 2 팀 A 발견) 워커 3개. 워커 보고서는 worker_a_1.md(A-1·A-5·0 레벨 처방), worker_a_2.md(A-2·A-3·A-4), worker_a_3.md(A-11 재실험·A-6 처방). 팀 리더가 별도로 5건을 독립 교차 확인했다.

Round 2의 스크립트와 수치는 쓰지 않았다. 워커 3개 모두 코드에서 조건을 새로 유도하고 실행 조건을 명시한 채 다시 측정했다. 저장소 코드는 한 줄도 고치지 않았고, 동작 변형은 전부 서브클래스 재정의와 monkey-patch로 처리했다.

1. 가설 목록

발견 가설 6개와 처방 가설 3개로 형식화했다.

ID가설
H1 (A-1)channel_llr가 top_level의 정수배면 iteration 1에서 raw = ch + Σ(±top_level) = 0 공명이 생기고, 균일 edge_mag의 마지막 레벨 0이 이를 magnitude 0으로 만들어 CN을 침묵시킨다. FER이 1.0으로 붕괴하며 경고 없이 완주한다
H2 (A-2)"uniform" in basename.lower() 부분문자열 검사 때문에 사람이 만든 3-bit DAO 파일 이름에 uniform이 부분문자열로 들면 edge_mag가 [7,5,3,1]에서 [3,2,1,0]으로 바뀌어 조용히 다른 결과를 낸다
H3 (A-3)생성된 3-bit 균일 파일에서 uniform이 빠지면 th_len == 3 검사를 통과해 edge_mag가 [3,2,1,0]에서 [7,5,3,1]로 조용히 바뀐다. 4-bit 이상만 NotImplementedError로 걸린다
H4 (A-4)sgn * 0이 -0.0이 되고 new_sgn = (vnu_out < 0)가 이를 양수로 읽어 부호가 사라진다. csw 로그와 final_csw가 이미 실사용에서 틀린 값을 낸다. 복호 결과는 바뀌지 않는다
H5 (A-5)magnitude 0이 <= 비교로 항상 min1을 차지해 그 CN이 min1_pos 하나를 뺀 모든 edge에 0을 보낸다. 원본 HW에 대응이 없고 FER이 나빠진다
H6 (A-11)균일 모드가 dv별 ch 차등을 표현하지 못하는 것이 FER을 나쁘게 한다. Round 2 실험은 ch/top_level 비율이 어긋나 인과 판정이 성립하지 않는다
P1 (A-5 처방)edge_mag 최소를 1로 바꾸면 A-1과 A-5가 동시에 해소되고, C++ C2V_Cal의 EDGE_MAG_1 = 1 복원과 정합하며, 부작용이 없다
P2 (A-4 처방)new_sgn = np.signbit(vnu_out)로 바꾸면 -0.0 부호가 보존되고 3-bit 파일 경로의 기존 동작이 비트 단위로 보존된다
P3 (A-6 처방)균일 매트릭스에서 캐스케이드를 `sign(raw)·min(raw, top_level)`로 대체하면 전 유효 입력에서 등가이고 교체 지점 구조와 충돌하지 않는다

2. 증거 확인 결과

2.1 팀 리더 독립 교차 확인 (워커와 별개로 직접 실행)

확인 항목결과
A-1 조건식 열거 검증`k<= dv-1 이면서 k ≡ dv-1 (mod 2)`가 raw=0 가능성과 dv ∈ {2,3,4,11} × k ∈ 0..5의 24/24 조합에서 일치
A-4 -0.0 기전float32(-1)*float32(0) = -0.0, (-0.0 < 0) = False, np.signbit(-0.0) = True, np.roll이 -0.0 보존
A-4 출력 경로prev_csw → log_csw_sum → sim.py:67 → run.py:448-449 csw_mean 열, final_csw → sim.py:77 → run.py:487-490 final_csw 열. 두 로그 모두 현재 config.json에서 기본 on
P1 실현 가능성edge_mag = [top..1]은 llr_matrix.py:74-76에서 즉시 ValueError
A-5 2중 손상min1=1·min2=3·min1_pos=5인 lane에 edge 9로 mag 0 투입 → 다른 edge C2V 0.0, min1_pos edge C2V 7.0(RESET)

  • ㉮ 3-bit 파일 경로 비트 단위 보존은 확인됨. LLR_MATRIX_HD_0.txt 45,301,760 원소와

자식 클래스가 mag를 정수 dtype으로 돌려주면 -0.0이 없어 처방이 조용히 무력해진다. 근본적 대안은 _vnu_quantize가 (sgn, mag) 쌍을 반환하는 구조이나 교체 지점 시그니처를 바꾸는 변경이라 등급이 올라간다

아이디어 자체는 유효하다. 속도 이득이 독립 재측정에서 호출 단위 th 3개 3.6배, 31개 19배, 127개 73.5배, 2047개 1172배로 확인됐다.

  • ㉮ "전 유효 입력에서 등가"를 "정수 raw에서 등가"로 좁혀야 한다. 비정수 raw에서

캐스케이드는 magnitude를 내림하고 대체식은 그대로 둔다 (top=31에서 raw 3.5 → 3.0 대 3.5). 팀 리더도 독립 확인했다. 지금 파이프라인은 정수만 만들지만, _c2v_reconstruct나 _vnu_quantize를 재정의하는 아이디어(offset·normalized min-sum, damping)가 비정수를 쉽게 만든다 (A-9와 같은 뿌리). 조건을 주석에 못 박거나 assert로 지켜야 한다

갈아 끼우지만 th 값은 파일에서 그대로 온다. 파일명 기반으로 두면 A-2·A-3와 같은 오탐 경로를 하나 더 만든다. 검증된 값 기반 판정식은 edge_mag가 [top..0]이고 row_th가 [top..1]인지 보는 것이며, 내부 합성본과 생성 파일에 True, DAO 3-bit 파일에 False를 주고 restart의 -1 th도 자동으로 걸러낸다

4. 처방 3개의 상호작용 (팀 리더 종합)

세 처방이 독립이 아니다. 이것이 이번 검증에서 나온 가장 중요한 종합 판단이다.

  • ㉮ P2와 P3를 그대로 함께 적용하면 조용히 동작이 갈린다. P3의 대체식이 raw == 0에서

+0.0을 주는데 P2가 np.signbit으로 부호를 읽기 때문이다. 각각을 따로 "유효"로 올리고 나중에 함께 넣으면 아무 경고 없이 결과가 달라진다

  • ㉯ P1을 채택하면 P2와 P3의 충돌이 함께 사라진다. 0 레벨이 없어지면 magnitude 0이 생기지

않아 -0.0이 원천적으로 발생하지 않고, P2가 고치려던 A-4 자체가 소멸한다. 팀 리더가 직접 확인했다: 안 ㉮ 하에서 _vnu_quantize 출력의 magnitude 0 건수와 부호 있는 0 건수가 각각 0이다

  • ㉰ P1 채택 시 P3의 대체식 형태가 바뀐다. np.sign(raw)·min(|raw|, top)이 아니라

**기존 부호 분기를 유지한 sgn · max(min(|raw|, top), 1)**이어야 한다 (np.sign(0) = 0이라 그대로 쓰면 magnitude가 0으로 무너진다). 팀 리더가 직접 대조해 raw −15..+15 전 구간, vnu_in 부호 양쪽에서 캐스케이드와 완전 일치함을 확인했다. 이 형태도 O(1)이라 속도 이득은 그대로다

  • ㉱ 권고 순서: P1을 먼저 결정한다 (Decision 등급, 사용자 확인 필요).
    • ㉠ P1 채택 시: A-4가 소멸하므로 P2는 불필요하다. P3는 sgn·max(min(|raw|,top),1) 형태로 적용한다
    • ㉡ P1 미채택 시: P2를 적용하고, P3는 raw == 0의 부호를 vnu_in에서 가져오도록 고쳐

-0.0을 보존해야 한다. 두 처방을 같은 커밋에서 함께 검증해야 한다
