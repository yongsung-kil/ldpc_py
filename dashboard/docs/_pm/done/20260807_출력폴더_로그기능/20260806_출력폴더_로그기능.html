LDPC_base 결과 폴더 구조화 + 분석 로그 출력 기능

등록: 2026-08-06 23:21:26 대상: 2_LDPC_light/_test/20260806_setup_구성_실험/LDPC_base/ (개정본) 착수 조건: 외부에서 진행 중인 LDPC 동작 확인 작업 완료 후 (다른 대기 작업들과 동일)

목적

  • ㉮ 실험 결과가 서로 덮어쓰지 않고 실행 단위로 보존되도록, Sim_Output/ 하위에

YYMMDD_HHMMSS_{라벨}/ 폴더를 만들어 그 안에 결과를 저장한다

  • ㉯ JSON에 로그 모드를 추가해, iteration별 CSW와 bit error(전체, DV별) 등

분석용 중간 로그를 출력할 수 있게 한다

1. 결과 폴더 구조화

Sim_Output/
└── 260806_231500_{라벨}/     ← 실행마다 생성 (YYMMDD_HHMMSS_라벨)
    ├── config.json            ← 실행에 쓴 설정 사본 (재현성)
    ├── fer_{채널}.csv         ← 기존 FER 결과
    ├── summary.txt            ← 콘솔 출력과 동일한 요약
    └── log_*.csv              ← 아래 로그 기능 출력 (켠 항목만)
  • ㉮ 라벨은 output.label로 받는다 (없으면 채널 이름 등으로 자동)
  • ㉯ 설정 사본 저장은 항상 수행 (재현성 확보, 용량 미미)
  • ㉰ 가능하면 git 커밋 해시도 summary에 기록 (코드 버전 추적)

2. 로그 모드 (JSON log 섹션)

단순 on/off가 아니라 항목별 선택으로 한다 (로그는 속도를 깎으므로 필요한 것만):

"log": {
  "csw_per_iter": true,        // iteration별 CSW (프레임별)
  "bit_err_per_iter": true,    // iteration별 잔여 bit error 수 (전체)
  "bit_err_by_dv": true,       // iteration별 잔여 bit error의 DV별 분해
  "flip_count_per_iter": false,
  "table_row_history": false,
  "iter_histogram": true,
  "fail_frame_detail": true,
  "fail_frame_positions": false
}

로그 항목 후보 (원본 C++ 로그와 대응 근거 포함)

항목내용원본 대응용도
csw_per_iteriteration별 CSW (프레임별 또는 평균, 분포)m_log_CSW, m_log_CSW_auto수렴 궤적, CSW 그룹 임계 튜닝
bit_err_per_iteriteration별 잔여 bit error 수 (genie 기준)m_log_bit_err수렴 궤적, restart 효과 확인
bit_err_by_dv위를 DV별로 분해m_log_bit_err_col의 축약판특정 DV 고착 진단 (예: 이번에 발견한 dv2 고정 문제)
bit_err_by_colcolumn block별 분해 (세밀판)m_log_bit_err_col위치 편중, 특정 블록 문제 진단
flip_count_per_iter이번 iteration에서 뒤집힌 bit 수해당 없음 (py 고유)진동, 정체 감지
table_row_historyiteration별 실제 선택된 테이블 row (CSW 그룹 진단)m_log_LLR_idxDAO 매트릭스가 의도대로 전환되는지 확인
min_sum_statsiteration별 min1/min2 합 또는 분포m_log_min1_sum, m_log_min2_sumCN 신뢰도 발달 관찰
iter_histogram성공 프레임의 수렴 iteration 히스토그램m_log_iter_histogram_tot평균 iteration 최적화, max_iter 여유 판단
fail_frame_detail실패 프레임별 최종 잔여 에러 수, 최종 CSW, DV별 분해corner 추적의 축약판error floor, trapping set 1차 진단
fail_frame_positions실패 프레임의 잔여 에러 bit 위치 덤프uncor vector 저장 대응trapping set 패턴 식별
fail_frame_seed실패 프레임 재현 정보 (seed, 프레임 인덱스)uncor_seed_*.txt 저장실패 케이스만 재실행하며 로그 정밀 분석
channel_stats채널 주입 실측 (프레임별 에러 수, 2SD strong/weak 비율)해당 없음채널 설정 검증

C++에는 없지만 통상적으로 쓰는 항목 (사용자 확정 2026-08-06: 아래 3개만 추가)

항목내용용도
post_fec_ber복호 후 BER (잔여 에러 bit 수 / 총 bit 수), FER와 함께 표준 지표논문, 스펙 비교는 FER와 BER 둘 다 요구되는 경우가 많음
fer_vs_iter프레임별 성공 iteration 기록으로 "max_iter를 k로 줄였다면"의 FER를 한 번의 실행에서 전부 산출max_iter 대비 성능 trade-off를 추가 실행 없이 분석 (수집 비용 거의 0)
fer_curve_png실행 폴더에 FER 커브 그림 자동 저장 (기존 fer_curve.py의 plot 재사용)결과 확인 편의

제외 확정 (사용자 코멘트 2026-08-06): fer_confidence(신뢰구간), miscorrection_count(undetected error 분리), injected_err_histogram(주입 에러 히스토그램)

구현 방식 메모

  • ㉮ decoder의 collect_profile을 확장하는 방향: _decode_matrix()에 로그 수집기 객체를

넘기고, 켜진 항목만 iteration 루프에서 수집 (배치 마스킹과 공존해야 함 — 프레임 제거 시 idx_active로 원 프레임 번호 유지)

  • ㉯ 출력은 사람이 읽는 CSV (프레임 수 × iteration 크기라 수 MB 수준, 문제없음).

fail_frame_positions만 커질 수 있어 실패 프레임 한정

  • ㉰ 로그를 켜면 속도가 떨어짐을 README에 명시 (특히 by_col, positions)
  • ㉱ VNU in/out 전체 덤프(원본 __LOG_VNU_IN_OUT__ 대응)는 용량이 커서 이번 범위에서 제외,

필요해지면 별도 등록

수정 대상 파일

  • LDPC_base/run.py — 출력 폴더 생성 (report 단계), config 사본 저장, log 섹션 파싱
  • LDPC_base/decoder.py — _decode_matrix() 로그 수집 훅
  • LDPC_base/sim.py — 로그 수집 결과 취합, 저장
  • config.json, README.md — 스키마 반영

미결정 사항 (착수 시 확인)

  • ㉮ 로그 항목 중 실제로 켤 기본 세트 (전부 구현 vs 우선순위 상위만 먼저)
  • ㉯ 폴더 라벨 규칙 (output.label 수동 vs 채널+포인트 자동 조합)
  • ㉰ fail_frame_seed 재현 방식 (numpy Generator 상태 저장 vs seed+카운터 기록)
