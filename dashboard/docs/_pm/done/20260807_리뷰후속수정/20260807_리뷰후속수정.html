3. strong_error 2단계 추출 재설계 (F1)

사용자 제안: ① N개 중 에러 개수 E만큼 무작위로 뽑고 ② 그중 round(E·SER)개만 무작위로 골라 strong 에러로 표시. 정상 비트 쪽 SCR도 같은 방식.

등가성 검토 결과 (적절함): 원본 C++는 균일 무작위 순열의 앞부분을 [strong 에러 | weak 에러 | weak 정상] 구간으로 잘라 쓴다. 균일 순열의 앞 e2개는 "E개 에러 집합에서 균일하게 뽑은 크기 e2의 부분집합"과 분포가 정확히 같으므로, 2단계 추출은 C++와 통계적으로 등가다. 정상 비트 쪽도 동일 논리로 "N−E개 중 균일 부분집합 c1개를 weak"이 성립한다. 순서 무작위성 요구 자체가 사라지므로 argpartition의 집합 균일성(검증 확인됨)만으로 충분해진다.

비용: 단계 ②는 프레임당 E(수백 개) 셔플이라 무시 가능. 정상 비트 쪽은 이미 만드는 (B, N) 난수를 재사용해 여집합에서 argpartition하면 추가 비용이 채널 생성 1회분 이내. 채널 생성은 디코딩 대비 미미하므로 성능 문제 없음.

주의: fixed_error가 쓰는 _rand_positions는 건드리지 않는다 (기존 결과 비트 단위 재현성 유지, r3 team_a 검증 결론).

4. F11 — _validate 제약 정리 (사용자 확정판 2026-08-07)

원칙: DAO 규칙이 정본이다. DAO는 실제 운용을 위해 만든 것이라 C++보다 rule이 정확하며, C++ 로더에 검사가 없는 것은 검증 내용을 빠뜨린 것일 뿐이다. 따라서 "C++에 근거 없음"은 제약 완화의 이유가 되지 않는다 (Round 3 처방 중 완화 항목을 사용자 지시로 되돌림).

제약처분
그룹 겹침 금지유지 (거부 = 오류) — 겹치는 파일은 오류가 있는 파일이다. _group_of_iter 정방향 순회와 한 쌍이라는 주석 추가
빈틈 금지 + iteration 1 시작 강제커버리지 검사로 교체 (동의) — 그룹 간 겹침 없이 1..max_iter 전 구간이 덮이는지 검사, 미커버 iteration 번호를 에러 메시지에 나열
restart 그룹 단일 row/단일 iteration유지 — restart는 row 1개여야 한다
restart 그룹 마지막 금지유지 (에러) — restart가 마지막 iteration이면 안 된다
