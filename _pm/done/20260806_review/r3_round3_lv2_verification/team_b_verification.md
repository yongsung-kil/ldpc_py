## 3. 판정

### F2 (HIGH). 판정: **부분 확인 (현상 확인, 원인 재분류)**, 처방: **유효 (보강 2건)**

- ㉮ 현상(dv=2 영구 미정정, 현행 config에서 FER ≡ 1.0)은 실측으로 확인됐다. "전량 실패"는 과하고 실측은 88.9% ~ 96.6%다.
- ㉯ 원인은 **구현 결함이 아니다**. Round 2가 남긴 두 갈래 중 "㉮ 도메인 불일치"는 **반박됐다**. C++ 원문도 5-bit ch와 3-bit EDGE를 같은 가산기에 섞고(`decoder.cpp:4026`, `:4041`, `:2402-2410`), 로더에 범위 검사도 클램프도 없다(`local_opt.cpp:52-132`). 결정적으로 벤더 자신의 3-bit 테이블이 63 row 전부 dv=2에 ch=10을 넣어 상한 14를 지킨다(`decoder.cpp:6777-6839`). 즉 `ch <= EDGE_MAG_7 * dv`는 원 설계의 **암묵 불변식**이고 토이 파일이 그것을 깼다.
- ㉰ **재분류: 토이 데이터 + 검출 장치 부재.** 심각도는 **HIGH 유지**다. 저장소 설정 그대로 실행하면 FER이 항상 1.0인데 사용자에게 가는 신호는 "FER 1.0"뿐이라 조용한 전멸이다.
- ㉱ 처방(생성자 검사)은 **유효**하다. 오탐 0건, 미탐 0건이고 부등식은 반전 불가의 필요조건으로 엄밀하다. 보강 두 가지:
  - ㉠ 경계는 `>=`가 아니라 **`>`**여야 한다 (ch = 7*dv이면 edge clear iteration에서 total = 0 도달 가능하고 `flip = total <= 0`이라 반전된다. 실측: ch=15는 0/17, ch=14는 13/17 정정).
  - ㉡ `dv_from != dv_to`인 일반 파일에서 미탐이 나지 않도록 구간 대표값이 아니라 `decoder.py:67`의 `self._col_dv`와 `code.col_deg`를 짝지어 **column 단위로** 검사해야 한다.
- ㉲ 데이터 조치도 병행 권고한다. 토이 파일의 dv=2 ch를 상한 이하로 내린다. 벤더 값 `{21, 14, 12, 10}`이 참고값이며 dv=2에 10을 넣으면 dv=2 단일 에러를 16/16 정정했다.
- ㉳ README:114-117은 **수정 필요**다. 네 곳:
  - ㉠ "전량"을 실측치(88.9% ~ 96.6%)로 바꾼다.
  - ㉡ "C++도 동일할 산술"에 "AUTO 빌드로 **같은 테이블 파일**을 읽을 때"라는 조건을 붙인다. 비AUTO 경로의 벤더 테이블은 dv=2에 ch=10이라 반전이 가능하다.
  - ㉢ "구현 버그 아님"이 "조치 불요"로 읽히지 않도록, 현행 config에서 FER ≡ 1.0이고 원인을 알리는 장치가 없다는 사실을 함께 적는다.
  - ㉣ "토이 매트릭스"라는 한정이 낙관적이다. `max_value`가 dv 구분 없이 31이라 최적화 탐색 공간 자체가 영구 미정정 구간을 포함한다.

### F8 (MEDIUM). 판정: **확인됨**, 처방: **수정 필요 (갈래 2 채택, 다만 `np.select` 대신 중첩 `np.where`)**

- ㉮ 처방 두 갈래 중 **갈래 2 (캐스케이드 교체)가 옳다**. 갈래 1(검사, 거부)은 C++이 정상 처리하는 파일을 Python이 거부하게 만들어, 루트 `CLAUDE.md` "프로젝트 간 흐름 ㉰"(외부의 H-matrix와 파라미터를 넣어도 동작하는 것이 목표)를 정면으로 위반한다. C++는 `local_opt.cpp:52-132`와 `decoder.cpp:7093-7095` 어디에서도 th 정렬을 검사하지 않는다.

- ㉰ **처방 원문의 `np.select`는 바꿔야 한다.** 실측에서 `np.select`는 현행 대비 1.339배 느리고, 중첩 `np.where`는 0.503배로 오히려 전체 실행을 9.1% 단축한다.
- ㉱ 적용 범위는 `_mx_vnu_quantize`(`decoder.py:93-96`)와 `_vnu_quantize`(`decoder.py:81`) **양쪽**이다. 후자는 F23(llr_tables 존치 여부 Decision)과 묶인다.

- ㉳ 등급: **Review** (로직 변경이나 현행 입력에서 동작 완전 보존).

| ㉯ | 빈틈 금지 + iteration 1 시작 강제 (`:80`, `:83-84`) | 형태(`s == prev_end + 1`)는 근거 없음. **커버리지 요구 자체는 C++에도 있다** (`decoder.cpp:7046-7051` 미커버 시 범위 밖 읽기) | **완화** (제거 아님) | `1..max_iter` 전 구간 커버리지 검사로 교체. `iter_start = 0` 허용, 미커버 iteration 번호를 메시지에 나열 |

| ㉱ | restart 그룹 마지막 금지 (`:93-94`) | **없음** (마지막이어도 `decoder.cpp:1120`, `:1133`, `:1951`, `:5350`으로 정상 판정) | **완화** (에러를 경고로) | `it == self.max_iter`면 `warnings.warn` |

- ㉲ 질문 A 답: **restart 마지막 금지 제거는 안전하다**. 실측에서 restart가 마지막인 iteration이 512프레임 중 445프레임을 스스로 성공 판정했다(대조군 0). "ch = -1이라 유효 판정 불가"라는 반대 논점은 반박됐다. 다만 restart는 잔여 에러를 2.4에서 1635.2로 늘리는 교란 단계라 뒤에 회복 iteration이 없으면 품질이 나쁘다. 그래서 완전 삭제보다 **경고 전환**을 권고한다.
- ㉳ 질문 B 답: **iter1 시작 강제를 그냥 제거하는 것은 반대한다**. 제거하면 로드 시 명확한 에러가 첫 배치 디코딩 도중 `ValueError`(`llr_matrix.py:158`)로 늦춰지는 퇴보다. C++조차 미커버 iteration에서 `selected_group = -1`로 `type_each_group[-1]`을 읽는 미정의 동작을 한다. 진짜 결함은 `s == 1` 형태가 C++ 합법인 `iter_start = 0`을 거부하는 것이므로, **커버리지 검사로 교체**가 맞다.
- ㉴ Round 2 처방 항목별 판정:
  - ㉠ "restart 마지막 금지 제거" → **부분 유효** (하드 에러 해제는 옳으나 경고 전환이 낫다)
  - ㉡ "iter1 시작 강제 제거" → **반대** (커버리지 검사로 교체가 맞다)
  - ㉢ "제약과 순회의 한 쌍 관계를 주석으로" → **유효** (실측으로 뒷받침됨)
  - ㉣ Round 2 미언급: restart 단일화 제약은 근거 전무이므로 **제거**, 빈틈 금지는 반대로 **유지 강화**
- ㉵ 등급: **Review** (배포 파일 2개는 새 검사식을 그대로 통과한다). 단 `_group_of_iter`를 역방향으로 바꾸는 대안을 택하면 **Decision**이다.

### F14 (MEDIUM). 판정: **반박됨 (결함 아님)**, 처방: **갈래 1 (현행 유지 + 문서화), 갈래 2 반대**

- ㉮ **V1과 V4는 양립 가능하다.** "정확성 문제 아님(V1)"과 "경로 간 비교 시 계통 오차 주의를 문서화(V4)"가 동시에 성립한다.
- ㉯ **V1이 옳다.** matrix 경로의 `<=`는 `decoder.cpp:4044-4045` 원문 강제이고, signed 두 경로는 C++에 대조할 원문이 아예 없다(원본은 flip/magnitude 도메인만 쓴다). 따라서 "matrix와 다르다"는 사실만으로는 결함의 근거가 못 된다.
- ㉰ **갈래 2(signed 경로를 `<=`로 통일)는 반대한다.** 무작위 tie-break 기준선(0.1536)이 `<`(0.1458)와 `<=`(0.1562) 사이에 있다. 즉 `<=`로 바꾸면 낙관 편향이 같은 크기의 비관 편향으로 뒤집힐 뿐이고, "세 경로가 통일됐다"는 잘못된 안심만 준다.
- ㉱ 두 동점의 뿌리가 다르다. flip 도메인 동점은 송신 codeword와 무관한 대칭 규칙이고, signed 도메인 동점 쏠림은 `encoder.encode()`가 all-zero만 돌려주는 데서(`encoder.py:16-19`) 온다. 규칙을 맞추는 것은 증상 대칭일 뿐 원인 대칭이 아니다.
- ㉲ **V4의 우려는 실질적이며 크기까지 확인됐다.** 워터폴에서 FER 상대 7% 차이, `avg_iter_ok`는 상시 0.7% ~ 3.5% 차이다. `plan.md:81`이 `two_set`을 "비교용으로 유지"라 명시하므로 문서화 대상이다. 다만 자동 비교 워크플로가 없어 지금 잘못된 수치를 내는 파이프라인은 없다.
- ㉳ 처방 내용:
  - ㉠ `decoder.py:170`, `:268`에 주석: signed 도메인 판정이며 all-zero 송신 전제에서 `total == 0`은 정답으로 집계된다는 점, C++ 대응 원문이 없는 자체 규칙이라는 점
  - ㉡ `decoder.py:398`에 주석: `decoder.cpp:4044-4045` 원문 강제이므로 바꾸면 안 된다는 점
  - ㉢ 실험 README 또는 plan.md의 경로 비교 항목에 계통 오차 실측치 기재 (워터폴 FER 상대 약 7%, `avg_iter_ok` 0.7% ~ 3.5%). 세 경로의 FER과 avg n_iter를 소수점 아래까지 직접 비교하지 말 것
  - ㉣ 장차 정량 비교가 필요해지면 올바른 도구는 `<=` 통일이 아니라 동점 무작위 tie-break 옵션 또는 실제 인코더 도입(무작위 codeword 송신)이다. 후자가 근본 해법이며 별건 과제다
- ㉴ 등급: **Safe** (코드 동작 변경 없음).
- ㉵ 남는 위험: 세 경로 유지 여부 자체가 미결(F23)이다. matrix 하나로 정리하면 F14는 자연 소멸한다.
