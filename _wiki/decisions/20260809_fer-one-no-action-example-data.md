## 맥락, 대안, 이유

- ㉮ 맥락
  - 저장소 예시 파일 `LLR_MATRIX_HD_0.txt`, `HD_1.txt`는 dv=2 열에 ch=28을 준다. 3-bit에서 C2V 최대 크기는 7이라 dv=2 열이 받는 반박은 커야 `7*2 = 14`다. 이 열의 비트는 어떤 iteration에서도 반전되지 않는다
  - 전체 비트의 약 11.6%가 영구 고정되어 기본 실행 FER이 1.0으로 수렴한다. 2026-08-06과 2026-08-08 딥 리뷰가 둘 다 HIGH로 잡았다
  - 2026-08-06 리뷰에서 "도메인 불일치 구현 결함" 가설은 반박됐다. C++도 채널 LLR과 3-bit edge를 같은 가산기에 섞고 로더에 범위 검사가 없다. 즉 `ch <= 7*dv`는 원 설계의 암묵 불변식이고 예시 파일이 그것을 깬 것이다
  - 검증에서 디코더 코드를 바꾸지 않고 예시 파일의 ch만 조건 안으로 낮추자 FER이 정상 범위로 돌아왔다
- ㉯ 거부한 대안
  - ㉠ 생성자에서 column 단위 `ch > edge_max*dv` 검사를 넣어 에러나 경고 (오탐 0, 미탐 0으로 확인됐으나 채택하지 않음)
  - ㉡ 예시 파일 값을 지금 수정
  - ㉢ 예시 파일과의 비율 비교로 균일 모드의 성능을 서술
- ㉰ 이유
  - 예시 파일은 실사용 대상이 아니다. 실물 H-matrix와 LLR 테이블 반입 시 교체된다 (사용자 확인 2026-08-09)
  - 2026-08-07 사용자 지시: 파일 파라미터는 나중에 수정하고 대신 "LLR 최적화 시 dv 범위 상한 고려"를 TODO에 등록한다. 테이블 값의 물리 제약은 파일 검증 후보이기 전에 최적화 탐색 범위다
  - 예시값과의 비율 비교는 판단 근거가 되지 못한다
- ㉱ 결과로 생긴 규칙과 비용
  - 반전 가능 조건 `ch <= 7*dv` (3-bit 기준, edge 최대 레벨에 그 비트의 dv를 곱한 값)를 LLR 최적화 탐색 범위 규칙으로 등재 (`_pm/TODO.md:29-31`)
  - 코드 검사는 두지 않아 "알려진 위반 상태"로 남는다 (`docs/profile/constraints.md:49`). 파라미터 수정 시점에 함께 처리한다
  - 2SD/3SD toy 파일(2026-08-09)은 이 조건을 지켜 만들었다
  - 균일 모드는 전 dv 공통 ch라 dv별 차등을 표현하지 못한다. 결함이 아니라 특성이며 dv 차등은 파일 경로로 한다
  - 이후 minsum_dual_clip 실험(2026-08-14)에서 클리핑이 조건을 `ch <= Q + (dv-1)*P`로 좁히는 원인 분석에 같은 식을 재사용했다
