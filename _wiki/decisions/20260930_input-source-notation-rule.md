## 맥락, 대안, 이유

- ㉮ 맥락
  - 프로파일 `docs/profile/constraints.md` 2절은 "문서와 로그에 적으면 안 되는 것"을 적는 자리다. 이 저장소에는 입력 파일 출처에 관한 명문 규칙이 없다
  - 출처나 공급자 실값을 가리키는 문구가 5곳 있다: `README.md:223`, `_pm/TODO.md:31`, `_pm/DONE.md` 1곳, 리뷰 보고 1건, C++ 정적 분석 문서 1건. 뒤 셋은 이력물이다
  - 외부 도구 이름(DAO: decoder auto optimizer, LLR 테이블 최적화 도구. Ref-C: 원본 C++ 시뮬레이터)은 코드 주석과 README 전반에서 쓰이며 코드를 읽는 데 필요하다. 문제는 공급자와 실값을 가리키는 문구뿐이다
  - 이미 있는 결정: 평가 대상 입력 파일 자체를 저장소에 넣지 않는다 (2026-07-30, `README.md:223`)
- ㉯ 선택지
  - 1. (권고) 규칙을 새로 만들지 않는다. 2절에는 기존 결정 "평가 대상 입력 파일 자체를 저장소에 넣지 않는다"만 옮겨 적고 출처 표기 규칙은 "없음(미확인)"으로 둔다. 본문 문서 수정 0
  - 2. "입력 파일의 공급자 이름과 공급자가 준 실값을 문서에 적지 않는다"를 규칙으로 올리고 문구 5곳을 고친다. 이력물 3곳은 개인 경로 판정(물음 2)과 같은 충돌이 생긴다. 물음 2에서 "그대로"를 골랐으면 이력물을 빼고 2곳만 고친다
- ㉰ 권고 이유와 예외
  - 프로파일은 확인된 규칙만 적는 문서다. 없는 규칙을 지어 넣기보다 사용자가 정한 뒤 적는 것이 맞다
  - 이 저장소를 밖에 공개할 계획이 있으면 2
  - 규칙 문구를 "출처 기재 금지"처럼 넓게 쓰면 코드 주석의 DAO, Ref-C까지 위반이 된다. 올린다면 "공급자 이름과 실값"으로 좁힌다
- ㉱ 현 상태와 비용
  - 현 상태는 1 (규칙 없음, 문구 그대로). 프로파일 2절은 기존 결정과 "미확인" 표시로 채워져 있다
  - 위키 작성 규칙(2026-09-30)은 이 판정과 별개로 공급자 이름과 실값을 위키에 옮기지 않는다
