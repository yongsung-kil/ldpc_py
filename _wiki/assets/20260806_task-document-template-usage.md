## 내용

- 근거: `_pm/tasks/_template/task.md:1-22`, `_pm/done/20260809_2SD3SD구현/20260809_2SD3SD구현.md`, `_pm/done/20260810_workspace전환/20260810_workspace전환.md`, `_pm/done/20260807_리뷰후속수정/20260807_리뷰후속수정.md`
- ㉮ 양식 (정본 `_pm/tasks/_template/task.md`)
  - ㉠ 머리 3줄: 작성 시각, 상태(설계 중 | 진행 중 | 검토 대기), 변경 등급(Safe | Review | Decision)
  - ㉡ 본문 6절: 목적, 배경, 설계, 수정 대상, 안전성 체크리스트, 미결정 사항(㉮㉯ 나열)
- ㉯ 실제 사용에서 굳어진 확장 절
  - ㉠ "착수 조건": 외부 작업 완료 대기나 사용자 지시 날짜를 적는다
  - ㉡ "개선 원칙"과 "개선 후보 (사전 조사)" 표: 후보 표에는 "확정안이 아님"을 명시한다
  - ㉢ "확정 사항 (사용자 결정 날짜)": 미결정 사항을 닫은 결과를 담는다
  - ㉣ "검증": 회귀 일치와 주입 실증 결과를 실행 폴더 이름과 수치까지 적는다
  - ㉤ 설계 근거가 길면 같은 폴더에 분석 문서를 따로 두고 설계 절 머리에 "근거는 X.md"만 적는다
  - ㉥ 문서 머리에 "대상: 경로"를 적어 어느 코드본을 고치는지 밝힌다
- ㉰ 미결정 사항 처리: 착수 시점에 사용자 확정으로 닫고, DONE 배경에 "미결정 N건 사용자 확정 (㉮ ㉯ ㉰)"로 요약한다. 미결정이 없으면 "없음 (승인 날짜, 확정 내용)"으로 적는다
- ㉱ 체크리스트 완료 표기: `[x]` 뒤에 실행 폴더 이름과 비교 결과 수치까지 붙인다
- ㉲ 리뷰 후속 문서 꼴: "리뷰 발견 | 확정 내용" 표, 발견별 설계 절, "미결" 절로 잔여 이관
- ㉳ 보존 규칙: 사용자 노트 원문은 손대지 않고 완료 폴더에 그대로 둔다. 폴더명 날짜(완료일)와 문서명 날짜(등록일)는 다를 수 있다

## 사용 방법

- ㉮ 언제: `_pm/TODO.md`에 코드 작업을 등록할 때 `_pm/tasks/{작업명}/{작업명}.md`를 양식대로 만든다. 문서 정리 같은 단순 작업은 TODO만 쓴다
- ㉯ 어떻게: 양식 6절을 먼저 채우고 필요한 확장 절만 더한다. 미결정 사항은 판정요청 꼴로 사용자에게 묻고 답을 "확정 사항" 절로 옮긴다
- ㉰ 주의: 확장 절 이름을 새로 만들지 않고 위 이름을 그대로 쓴다. 완료 시 폴더째 `_pm/done/{YYYYMMDD}_{주제}/`로 옮기고 분석 문서와 노트 원문도 함께 옮긴다
