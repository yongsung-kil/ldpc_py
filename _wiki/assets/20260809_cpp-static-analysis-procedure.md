## 내용

- 근거: `_pm/done/20260809_2SD3SD구현/cpp_sd_analysis.md` (절 0~10 구성), `_pm/done/20260809_2SD3SD구현/20260809_2SD3SD구현.md:25, 47-48`, `src/decoder.py:122-123, 297-299, 351-354`
- 절차 11단계 (분석 문서의 절 순서가 곧 절차다)
  - 1. 머리: 대상 파일, 목적(어느 Python 함수에 이식하는지), 빌드 전제(어느 매크로가 정의된 빌드인지), 범위 밖 빌드는 각주로만, 근거 표기 규칙(`파일:줄`)
  - 2. 한 줄 요약: 이식에서 실제로 바뀌는 것만 먼저 적는다 (2SD/3SD 사례는 셋: 채널 항 선택, Pre 단계 시딩, Edge Clear 집합)
  - 3. 흐름 추적: 채널 플래그에서 magnitude, ch 인덱스, 파일 열 오프셋까지 함수 사슬을 끝까지 따라가 닫힌 식으로 정리한다
  - 4. 비교표: 항목 / 원본 경로 A / 원본 경로 B / 판정(같다, 다르다)로 산술 단계마다 판정한다. "같다"가 곧 "손대지 않는 곳"이다
  - 5. 어긋나 보이는 코드 쌍은 상태 추적으로 일관성을 입증한다 (예: edge sign을 서로 다른 iteration에서 읽는 함수 둘의 결과가 같음)
  - 6. 상수 목록을 "살아 있는 값"과 "소실된 값"으로 나눈다. 선언만 있고 초기화식이 없는 배열은 소실로 분류한다
  - 7. 범위 밖이지만 그 경로에만 있는 특이 동작을 나열하고 미구현 사유를 붙인다
  - 8. Python 이식 지점을 함수별로 매핑한다. "손대지 않아도 되는 곳"과 문서 갱신 항목(`docs/차이.md`)까지 적는다
  - 9. 확인 불가 항목을 명시한다 (소스 손상, 인코딩 깨짐, 빌드 미실행이라 정적 독해뿐)
  - 10. 반영: 코드 docstring에 C++ 함수 이름과 줄 번호를 남기고 (`src/decoder.py:122-123` 시딩 상수, `:297-299` Pre 단계, `:351-354` SD restart), 태스크 문서 설계 절은 "근거는 분석 문서"로 참조한다
  - 11. 실증: 설계에서 예측한 동작을 실행으로 확인한다 (예: SD restart iteration에서 에러 수가 채널 에러 수로 복귀)
- ㉮ 이름 원칙: 원본 주석의 이름을 그대로 쓴다 (very strong, normal weak 등). 원본에 없는 Python 표기는 "C++에 대응 매크로 없음"이라고 밝힌다
- ㉯ 결과물 위치: 분석 문서는 태스크 폴더 안, 코드에는 docstring의 `decoder.cpp:줄` 참조, 원본과의 차이는 `docs/차이.md`

## 사용 방법

- ㉮ 언제: 원본 C++ 기능을 Python 본체에 새로 이식할 때 (모드 추가, 미구현 경로 재현). 빌드나 실행이 불가능한 원본에도 쓴다
- ㉯ 어떻게: 단계 1~9를 분석 문서 한 편으로 먼저 끝내고 코드를 연다. 코드 수정은 단계 8의 매핑표대로만
- ㉰ 주의: 단계 6의 소실된 값은 추정값으로 메우되 추정임을 문서에 남긴다. 이 사본에는 C++ 원본이 없어 분석 문서의 C++ 줄 번호를 재대조할 수 없다
